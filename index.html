The limit isn't yours. It belongs to the model.

Every other API gives you a personal quota to burn through. OpenFlow gives each model one bucket and everybody drinks from it. Your key says who you are — it doesn't buy you a private allowance. Free, no tiers, no card.

Three steps to your first call

  1. Make an account

    Email and password. Signing up mints your owner ID, which every key you create is tied to.

  2. Generate a key

    The dashboard shows it once. Copy it then — only its fingerprint is stored, so it can't be shown again.

  3. Point your client here

    Anything that speaks the OpenAI chat format works. Swap the base URL and the key, keep the rest.

It looks like every other chat API

Because it is one. The only thing that changes is the base URL:

https://api-openflow.serveousercontent.com

# curl
curl https://api-openflow.serveousercontent.com/v1/chat/completions \
  -H "Authorization: Bearer of_live_your_key" \
  -H "Content-Type: application/json" \
  -d '{"model":"llama-3.3-70b","messages":[{"role":"user","content":"hi"}]}'

# python, no SDK required
import requests
r = requests.post(
    "https://api-openflow.serveousercontent.com/v1/chat/completions",
    headers={"Authorization": "Bearer of_live_your_key"},
    json={"model": "kimi-k2",
          "messages": [{"role": "user", "content": "hi"}]},
)
print(r.json()["choices"][0]["message"]["content"])

Streaming works — pass "stream": true and read the event stream as usual.

What happens when a model is full

Your request waits a few seconds for a slot. If none opens, you get a 429 naming the model, its limit, and how long until the next opening. That isn't a penalty aimed at you — someone else was mid-call. Switch to a model with room, or wait it out. The gauges above tell you which is which before you send anything.
